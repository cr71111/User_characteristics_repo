# 《两轮车换电平台用户运营分析体系》报告逻辑及计算方法

---

## 一、整体数据流程（Pipeline 四层架构）

报告的底层数据经过 4 层流水线处理：

```
L1: Event Layer（事件层）
 └─ 采集原始换电/骑行事件
      ↓
L2: Snapshot Layer（快照层）→ 输出 user_daily.parquet
 └─ 每人每日聚合指标（99个字段）
      ↓
L3: Lifecycle Layer（生命周期层）→ 输出 user_7d.parquet
 └─ 7天滚动聚合 + 月度预估 + 生命周期判定 + 用户画像
      ↓
L4: Score Layer（评分层）→ 输出 score_user_profile.csv
 └─ 动态阈值评分 + 等级分类 + 风险标签 + 策略建议
```

## 二、核心指标看板 — 计算方法

### 2.1 总用户数
**原始数据**：L3 输出表中的去重 `用户id` 数量。

### 2.2 活跃用户数
**计算公式**：
$$
\text{活跃用户} = \text{COUNT}(\text{近7d出勤天数} \ge 1)
$$

即近7天内至少出勤1天的用户。数据来源：[lifecycle_layer.py](file:///e:/OneDrive/DataBase/User_characteristics_repo/src/pipeline/lifecycle_layer.py) 中 `determine_lifecycle_state()` 函数，出勤天数 >= 5 判定为「活跃」，1-4 天为「轻度活跃」，0 天根据是否有数据区分「沉默」或「流失」。

### 2.3 日活率
$$
\text{日活率} = \frac{\text{活跃用户数}}{\text{总用户数}} \times 100\%
$$

### 2.4 周留存率
$$
\text{周留存率} = \frac{\text{近7天仍有数据的用户数}}{\text{上周有数据的用户数}} \times 100\%
$$

### 2.5 平均骑行里程
取自 `近7d单合约日均行驶里程_km` 字段的全体用户均值。
**计算方法**：[lifecycle_layer.py](file:///e:/OneDrive/DataBase/User_characteristics_repo/src/pipeline/lifecycle_layer.py) 中的 `_weighted_avg()` — 以时间衰减权重加权平均：
$$
\text{加权平均} = \frac{\sum_{i=1}^{7} (v_i \times w_i)}{\sum w_i}, \quad w = [1.0, 0.9, 0.8, 0.7, 0.6, 0.5, 0.4]
$$
权重按距今天数递减（最近一天权重最高=1.0，7天前权重最低=0.4）。

### 2.6 人均换电次数
取自 `近7d日均换电次数` 的全体用户均值。日均为总次数 / 有效天数。

### 2.7 高风险用户占比
$$
\text{高风险用户占比} = \frac{\text{风险标签} \neq \text{'正常'}  \text{的用户数}}{\text{总用户数}} \times 100\%
$$

### 2.8 优质用户占比
$$
\text{优质用户占比} = \frac{\text{用户等级\_动态} = \text{'优质用户'} \text{的用户数}}{\text{总用户数}} \times 100\%
$$

### 2.9 高损耗用户占比
$$
\text{高损耗用户占比} = \frac{\text{用户等级\_动态} = \text{'高损耗用户'} \text{的用户数}}{\text{总用户数}} \times 100\%
$$

### 2.10 夜间高风险用户数
`夜间高速风险 = '高'` 的用户数。判断逻辑见 5.1 节。

### 2.11 用户生命周期健康度
各生命周期状态（活跃/轻度活跃/沉默/流失/新用户/已到期）的分布占比，从 `用户生命周期状态_7d` 字段统计。

## 三、用户等级分布 — 计算方法

### 3.1 重评分数 计算体系

核心代码位于 [score_layer.py](file:///e:/OneDrive/DataBase/User_characteristics_repo/src/pipeline/score_layer.py) 的 `score_and_classify()` 函数。满分 100 分，由 **6 个维度打分 + 3 类惩罚/奖励** 加权构成。

#### 3.1.1 六维度打分（每人基于动态分位数对标）

所有分位数门槛来自 `DynamicBatteryAnalyzer.run()` 基于当前用户群体的动态计算，非固定值。以当前基线数据为例：

| 维度 | 字段 | 评分规则 | 满分 |
|------|------|----------|------|
| **平均骑行电流** | `近7d平均骑行电流_A` | ≤ P25（≈11.7A）→ 18分 / ≤ P50（≈16.4A）→ 10分 / ≤ P75（≈22.3A）→ 4分 / > P75 → 线性递减至0 | 18 |
| **最大电流** | `近7d最大电流_A` | ≤ P25（≈39.5A）→ 18分 / ≤ P50（≈46.2A）→ 10分 / ≤ P75（≈57.9A）→ 4分 / > P75 → 递减 | 18 |
| **百公里电耗** | `近7d百公里电耗_kWh` | ≤ P75（≈10.6kWh）→ 18分 / ≤ P90（≈13.8kWh）→ 10分 / ≤ P95（≈17.0kWh）→ 4分 / > P95 → 递减 | 18 |
| **低SOC时长占比** | `近7d_SOC低于20%时长占比` | ≤ P25（≈1%）→ 18分 / ≤ P50（≈2%）→ 10分 / ≤ P75（≈3%）→ 4分 / > P75 → 递减 | 18 |
| **包月友好分** | `近7d平均包月友好分` | ≥ P75（≈81.9）→ 18分 / ≥ P50（≈69.0）→ 10分 / ≥ P25（≈51.2）→ 4分 / < P25 → 线性递减 | 18 |
| **超80A次数** | `近7d电流超80A总次数` | ≤3次 → 20分 / 3~6次 → 20-(n-3)×2 / 6~10次 → 14-(n-6)×3 / >10次 → 减至0 | 20 |

理论满分：18+18+18+18+18+20 = **110分**（最终 clipped 到 100）。

#### 3.1.2 惩罚项（扣分）

| 惩罚项 | 触发条件 | 扣分 |
|--------|----------|------|
| 怠速放电惩罚 | 日均怠速放电 > 5h → -20 / > 3h → -10 | -20 ~ 0 |
| 温度惩罚 | 最高温度 ≥ 70°C → -8 / ≥ 55°C → -4 | -8 ~ 0 |
| 速度惩罚 | 最高速度 ≥ 80km/h → -10 / ≥ 60km/h → -6 / ≥ 50km/h → -3 | -10 ~ 0 |
| 换电频次惩罚 | 日均换电 > 5次 → -12 / > 3次 → -6 / > 2次 → -3 | -12 ~ 0 |

#### 3.1.3 奖励项

| 奖励项 | 触发条件 | 加分 |
|--------|----------|------|
| SOC黄金区间奖励 | 平均骑行SOC在30%~80%之间 且 SOC低于20%时长为0 | +3 |

#### 3.1.4 暴力度折扣系数

| 条件 | 折扣 |
|------|------|
| 近7天超100A连续次数 ≥ 2次 | 总分 × 0.3 |
| 近7天超100A连续次数 = 1次 | 总分 × 0.7 |

#### 3.1.5 沉默用户固定分

若 `avg_cur == 0 & max_cur == 0 & monthly_energy == 0 & ride_hours == 0`，固定给 20 分。

---

### 3.2 用户等级分类逻辑

基于 `重评分数` + `风险标签` 交叉判定，核心规则如下（按优先级从上到下执行，命中即停止）：

```
优先级1：沉默判定
├── avg_cur=0, max_cur=0, monthly_energy=0, ride_hours=0 →「沉默用户」(固定20分)

优先级2：暴力判定
├── 超100A连续 ≥ 2次 OR 超100A累计 ≥ 0.5h OR 最大电流 > P99 OR 月用电 > 250度
└── →「暴力」

优先级3：高风险交叉判定（超保护板电流 / 频繁超80A / 中高电流频繁）
├── 重评分数 ≥ P_normal →「普通用户」
└── 重评分数 < P_normal →「高损耗用户」

优先级4：中等风险交叉判定（月用电超标）
├── 重评分数 ≥ P_excellent →「良好用户」
├── P_good ≤ 重评分数 < P_excellent →「良好用户」
├── P_normal ≤ 重评分数 < P_good →「普通用户」
└── 重评分数 < P_normal →「高损耗用户」

优先级5：新兵保护期（入网 ≤ 3天）
└── →「观察期」

优先级6：高耗电判定（150度 < 月用电 ≤ 250度）
└── →「高损耗用户」

优先级7：正常用户按分数分级
├── 重评分数 ≥ P_excellent（≈P75，约75分）→「优质用户」
├── P_good（≈P55，约70分）≤ 重评分数 < P_excellent →「良好用户」
├── P_normal（≈P35，约50分）≤ 重评分数 < P_good →「普通用户」
└── 重评分数 < P_normal →「高损耗用户」
```

**分位数动态门槛说明**：
- `P_excellent` = 活跃用户重评分数的 P75（75%分位数）
- `P_good` = 活跃用户重评分数的 P55（55%分位数）
- `P_normal` = 活跃用户重评分数的 P35（35%分位数）
- 样本不足30人时回退为固定值：85 / 70 / 50

## 四、风险标签体系 — 计算方法

风险标签在 [score_layer.py](file:///e:/OneDrive/DataBase/User_characteristics_repo/src/pipeline/score_layer.py) 的 `score_and_classify()` 函数中生成，由 **4 类子标签用 「 / 」拼接** 组成：

### 4.1 电流风险标签（互斥，优先级从高到低）

| 标签 | 触发条件 | 阈值来源 |
|------|----------|----------|
| **暴力放电** | 超100A连续 ≥ 2次 或 超100A累计 ≥ 0.5小时 | 硬阈值 |
| **极端电流** | 最大电流 > P99（≈81.9A），且非暴力 | 动态分位数 |
| **超保护板电流** | 最大电流 > 60A（保护板硬阈值），且非暴力/极端 | 硬阈值 |
| **频繁超80A** | 超80A次数 > 0，且非以上级别 | 硬阈值 |
| **中高电流频繁** | 超60A次数 > 10，且非以上级别 | 硬阈值 |
| **持续高耗流** | 平均电流 > P95（≈32.1A），且非以上级别 | 动态分位数 |

### 4.2 SOC风险标签（互斥）

| 标签 | 触发条件 |
|------|----------|
| **持续深度亏电** | SOC < 10% 时长占比 > 5% |
| **深度亏电** | 最低SOC < 10% 或 SOC < 10% 时长占比 > 0 |
| **低SOC告警** | SOC < 20% 时长占比 > 0 |

### 4.3 电量风险标签

| 标签 | 触发条件 |
|------|----------|
| **月用电超标(N度)** | 月度预估电量 > 150 度（盈亏线），动态拼接实际预估值 |

### 4.4 温度风险标签（互斥）

| 标签 | 触发条件 |
|------|----------|
| **电池高温告警(>70°C)** | 近7天最高温度 ≥ 70°C |
| **电池温度偏高(>55°C)** | 近7天最高温度 ≥ 55°C |

### 4.5 疑似静态储能标签

额外判定条件（追加在上述标签后面）：

| 标签 | 触发条件 |
|------|----------|
| **疑似静态储能** | 怠速放电/总放电 > 80% 且 活动半径 < 2km 且 日均放电 > 1h |

## 六、生命周期结构分析 — 计算方法

### 6.1 生命周期状态判定

核心函数：[lifecycle_layer.py](file:///e:/OneDrive/DataBase/User_characteristics_repo/src/pipeline/lifecycle_layer.py) 的 `determine_lifecycle_state()`，判定优先级如下：

```
优先级1：合约到期
├── 合约到期时间 < 当前日期 →「已到期」

优先级2：新用户
├── 首次入网日期距今天数 ≤ 3天 →「新用户」

优先级3：沉默/流失
├── 近7d出勤天数 = 0
│   ├── 近7天有效数据天数 ≤ 1 →「流失」
│   └── 近7天有效数据天数 > 1 →「沉默」

优先级4：活跃程度
├── 近7d出勤天数 ≥ 5 →「活跃」
└── 近7d出勤天数 1~4 →「轻度活跃」
```

### 6.2 关键阈值

| 参数 | 值 | 说明 |
|------|-----|------|
| MIN_DAYS_FOR_ACTIVE | 5天 | 判定「活跃」的出勤天数门槛 |
| MIN_DATA_DAYS_TO_AVOID_CHURN | 1天 | 区分「沉默」和「流失」的数据天数门槛 |
| NEW_USER_DAYS | 3天 | 新用户保护期 |

### 6.3 核心指标计算

| 指标 | 计算方法 |
|------|----------|
| 生命周期人数 | 各状态 COUNT DISTINCT `用户id` |
| 生命周期转化率 | 某状态下用户 → 下一个更活跃状态的比率（需时序对比） |
| 生命周期流失率 | 活跃/轻度活跃 → 流失 的比率 |
| 生命周期留存率 | 本周仍活跃 / 上周活跃 |

## 七、月度用电预估 — 计算方法

核心函数：[lifecycle_layer.py](file:///e:/OneDrive/DataBase/User_characteristics_repo/src/pipeline/lifecycle_layer.py) 的 `calc_user_monthly_attendance()`。

### 7.1 计算逻辑

基于用户历史全量快照数据，三级估算体系：

```
Step 1: 有效日判定
├── 用电量 > 0 → 计为出勤日
└── 排除"数据完整性=不完整"的日期

Step 2: 分档计算月度预估工作天数
├── 完整记录天数 < 7 → 兜底值 26天
├── 7 ≤ 完整记录天数 < 30 → 实际出勤率 × 30天
└── 完整记录天数 ≥ 30 → 实际出勤率 × 30天

Step 3: 计算月度用电预估
单合约月度用电度数预估 = 日均用电量 × 月度预估工作天数
```

### 7.2 公式

$$
\text{出勤率} = \frac{\text{有效出勤天数}}{\text{完整记录天数}}
$$

$$
\text{月度预估工作天数} = 
\begin{cases}
26 & \text{记录天数} < 7 \\
\text{出勤率} \times 30 & \text{记录天数} \ge 7
\end{cases}
$$

$$
\text{月度用电预估} = \text{历史单合约日均用电量} \times \text{月度预估工作天数}
$$

### 7.3 关键阈值

| 参数 | 值 | 说明 |
|------|-----|------|
| MIN_RECORD_DAYS | 7天 | 低于此天数使用兜底值 |
| FULL_RECORD_DAYS | 30天 | 高于此天数为完全累计计算 |
| DEFAULT_MONTH_DAYS | 26天 | 兜底工作天数 |
| MONTH_CALENDAR_DAYS | 30天 | 月度日历天数 |

## 八、7天滚动指标 — 计算方法

核心函数：[lifecycle_layer.py](file:///e:/OneDrive/DataBase/User_characteristics_repo/src/pipeline/lifecycle_layer.py) 的 `calc_rolling_7d_metrics()` 和 `_calc_single_user_7d_rolling()`。

### 8.1 时间衰减权重

从最新日期往前7天，权重逐步衰减：

$$
w = [1.0, 0.9, 0.8, 0.7, 0.6, 0.5, 0.4]
$$

- 第 i 天（today-i）权重 = ROLLING_WEIGHTS[i]

### 8.2 各类聚合方式

| 聚合类型 | 字段示例 | 计算方法 |
|----------|----------|----------|
| **加权平均** | 日均行驶里程、骑行时长、均速、百公里电耗、包月友好分、SOC相关 | $\frac{\sum(v_i \times w_i)}{\sum w_i}$ |
| **加权比例** | 高峰骑行占比、SOC < 20%/10% 占比 | $\frac{\sum(r_i \times d_i \times w_i)}{\sum(d_i \times w_i)}$，以骑行时长为分母 |
| **最大值** | 最高速度、最大电流、最高温度、活动半径、覆盖面积、最远出行 | $\max(v_1, v_2, ..., v_7)$ |
| **最小值** | 最低SOC | $\min(v_1, v_2, ..., v_7)$ |
| **累计值+日均** | 骑行次数、换电次数、超流次数、各时段里程/骑行/换电 | $\sum v_i$ / $\frac{\sum v_i}{\text{有效天数}}$ |

### 8.3 工作特点判定 (`get_work_pattern`)

两阶段判定：

**第一阶段（长时骑行次数主导）**：
- 统计午间高峰/晚间高峰/平峰/夜间四个时段的长时骑行次数
- 若主时段占比 ≥ 50%，直接输出该时段模式
- 否则输出 "全天"

**第二阶段（里程主导，回退）**：
- 若长时骑行数据不足，用各时段总里程计算
- 同理，若主时段占比 ≥ 50%，输出该时段模式
- 否则输出 "全天"

时段定义（来自日级快照）：
- 午间高峰：约 11:00-13:00
- 晚间高峰：约 17:00-19:00  
- 平峰：非高峰时段
- 夜间：约 22:00-06:00

## 九、策略建议体系

## 十、用户画像体系 — 计算方法

核心函数：[lifecycle_layer.py](file:///e:/OneDrive/DataBase/User_characteristics_repo/src/pipeline/lifecycle_layer.py) 的 `_generate_full_portrait()` — 按固定模板生成文本画像。

### 10.1 画像文本模板（每个人一段完整描述）

```
【类型】{用户形态} | {用户等级} | 生命周期:{状态}
【骑行时间】惯用时段:{工作特点} | 首次上路:{首次骑行时间} / 最晚收车:{最晚收车时间} | 出勤率:{出勤率} | 日均骑行:{骑行时长}h
【换电习惯】{换电时段偏好} | 7天共换电{N}次 | 平峰占比:{p1} / 深夜占比:{p2} | 换电友好分:{分}/20
【活动区域】{省市区} | 日常半径(R90):{km}km / 极限半径(R95):{km}km | 覆盖面积:{km²}km² | 最远单次出行:{km}km | 集中度:{标签}
【骑行距离】7天:{km}km / 日均:{km}km | 百公里电耗:{kWh}kWh | 月预估用电:{度}度
【速度画像】P50:{km/h}km/h / P90:{km/h}km/h / 峰值:{km/h}km/h | 夜间均速:{km/h}km/h（风险:{等级}）
【电流画像】均值:{A}A / 峰值:{A}A | 超80A:{次}次 | 超100A连续:{次}次
【电池状况】最低SOC:{soc}% / 均值SOC:{soc}% | 低电量时长占比:{pct} | 取电SOC:{soc}% → 还电SOC:{soc}%（消耗:{soc}%）
【风险&策略】{风险标签} | {策略建议} | 综合评分:{score}/100
```

### 10.2 画像衍生指标

| 衍生指标 | 计算方法 | 来源函数 |
|----------|----------|----------|
| **活动集中度** | R90半径 / 最大半径，clip到[0,1] | `_add_derived_portrait_metrics` |
| **换电友好分** | (平峰占比 × 0.6 + 深夜占比 × 0.4) × 20，满分20 | `_add_derived_portrait_metrics` |
| **换电时段偏好** | 平峰占比 ≥ 50% → 偏好平峰换电 / 深夜 ≥ 40% → 偏好深夜换电 / 平峰+深夜 ≥ 50% → 混合 / 高峰 ≥ 60% → 高峰为主 / 否则 → 时段分散 | `_add_derived_portrait_metrics` |
| **骑行规律性评分** | 出勤率 × 10，满分10 | `_add_derived_portrait_metrics` |
| **夜间高速风险** | 夜间均速 ≥ 45km/h → 高 / ≥ 35km/h → 中 / 其他 → 低 | `_add_derived_portrait_metrics` |
