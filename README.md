# 用户特征画像项目 - 两轮车换电用户分析系统

## 📖 项目简介

本系统是一套完整的**两轮车换电用户特征画像分析平台**，实现从原始 IoT 传感器数据到最终用户画像报告的全自动化数据流水线。

### 核心能力

- **多维度用户画像**：骑行行为、电池使用、换电习惯、活动范围、速度/电流特征等 9 大维度
- **智能分类体系**：基于动态阈值的用户等级评定（优质/良好/普通/高损耗/暴力/观察期/沉默）
- **风险预警机制**：电流异常、深度亏电、高温告警、夜间高速等多重风险识别
- **策略建议生成**：结合客户形态和工作特点的差异化运营建议
- **完全体画像输出**：结构化的文本画像，一目了然地展示用户全貌

## 🔄 数据流水线架构

### 整体流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                        数据流水线 (L0 → L4)                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  原始CSV          合约级日指标        用户级快照       7天滚动档案     报告
│  (IoT传感器)    →  (Fact Layer)  →  (Snapshot)  →  (Lifecycle)  →  Markdown
│                                                                     │
│  L0              L1                L2              L3+Score       L4
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 五层架构详解

| 层级 | 模块 | 输入 | 输出 | 核心职责 |
|------|------|------|------|----------|
| **L0** | `raw_ingest.py` | 原始 CSV 文件 | `raw/{date}.parquet` | 原始数据清洗、标准化、按日期归档 |
| **L1** | `fact_layer.py` | Raw Parquet | `fact/daily/{date}.parquet` | 合约级日指标计算（骑行、电流、温度、SOC等） |
| **L2** | `snapshot_layer.py` | Fact Parquet | `snapshot/user_daily.parquet` | 用户级日聚合（多合约合并、空间统计） |
| **L3** | `lifecycle_layer.py` | Snapshot Parquet | `lifecycle/user_7d.parquet` | 7天滚动窗口计算、衍生指标、完全体画像文本 |
| **L3+** | `score_layer.py` | Lifecycle DataFrame | （内存中） | 动态阈值计算、评分分类、风险标签、策略建议 |
| **L4** | `report_layer.py` | Scored DataFrame | `reports/*.md` | 生成结构化分析报告 |

## 📊 核心业务逻辑

### 1️⃣ L0 - 原始数据摄入层 (`raw_ingest.py`)

**功能：** 将原始 IoT CSV 数据转换为标准化的 Parquet 格式

**核心特性：**
- ✅ **高性能批处理**：8进程并行，每批100文件，支持8000+文件快速处理
- ✅ **智能文件过滤**：预读前50行提取日期，跳过已有数据的日期（节省90%+ I/O）
- ✅ **增量处理**：自动检测已存在日期，只处理缺失数据
- ✅ **数据清洗**：
  - 在线状态过滤（只保留在线记录）
  - 中国境内GPS粗过滤（排除异常坐标）
  - 数值类型转换与标准化
  - 字段名统一映射

**输入字段：**
```
时间戳, 合约id, 用户id, 纬度, 经度, 电流, 温度, 速度,
电池SOC, 电池度数, 电池id, 是否在线, 统计日期
```

**输出：**
- 路径：`data/raw/{YYYY-MM-DD}.parquet`
- 格式：Parquet（snappy压缩）
- 特点：按日期分文件，便于增量处理

### 2️⃣ L1 - 客观事实层 (`fact_layer.py`)

**功能：** 计算每个合约每天的详细指标（最复杂的计算层）

**核心计算维度（20+类指标）：**

#### 🚴 骑行状态判定
```python
# 复合条件判定（主骑行 + 辅助骑行）
main_ride_condition = (
    相邻距离 >= 最小有效位移 AND
    0 < 速度 <= 最大有效速度 AND
    电流 > -20A
)

# 平滑处理（3点滑动窗口最大值，消除抖动）
骑行状态 = main_ride_condition OR assist_ride_condition
         → rolling(window=3).max()
```

#### 📏 空间活动指标
- **R90/R95半径**：90%/95%分位数的活动半径
- **凸包面积**：基于ConvexHull算法的覆盖面积
- **最大出行距离**：单次最远出行距离
- **中心坐标**：加权质心（基于时间戳）

#### ⚡ 电流特征
- **平均/峰值/标准差/变异系数**
- **高峰vs平峰电流差异**（午间11-13点 + 晚间17-19点）
- **超阈值次数**：>60A / >80A / ≥100A（连续3次判定）
- **超100A累计时长**

#### 🔋 电池健康度
- **SOC指标**：平均值、最低值、<20%时长占比、<10%时长占比
- **能耗指标**：总用电量(kWh)（SOC差法计算）、百公里电耗
- **换电次数**：基于电池ID切换检测

##### ⭐ 用电量计算（SOC差法，v1.7+）
```python
# 公式：E_kWh = Σ (标准电压_V × 容量/SOC / 1000) × (SOC差 / 100)
# 按电池id分组，换电时(SOC上升>1%)重新计算初始容量
# 标准电压从 电池单体电压.csv 查表获取，未匹配则默认60V
```

#### 🌡️ 温度 & 速度
- **温度**：最大值、最大时刻、平均值
- **速度**：最大值、P50/P90分位数、夜间均速、高速点数(>40km/h)

#### 🔌 换电时段分析（新增）
- **时段分布**：平峰(6-11,14-17点) / 深夜(20-6点) / 高峰
- **偏好时段**：基于众数判定
- **取电/还电SOC**：每次换电的SOC变化

#### ⏰ 骑行时刻分布（新增）
- **最早/最晚骑行时刻**
- **主要骑行时段**：午间高峰 / 晚间高峰 / 夜间 / 平峰

#### 👤 客户形态判定
| 形态 | 判定条件 |
|------|---------|
| **改装/超速车** | 速度>50km/h 或 电流>24A |
| **地摊/储能** | 距离<1km 且 速度<3km/h 且 怠速比高 |
| **专送骑手** | 出勤率高 + 高峰骑行占比高 |
| **众包骑手** | 中等活跃度 |
| **标准骑手** | 正常使用模式 |
| **普通骑手** | 低频使用 |

#### 📊 包月友好评分（100分制）
```python
基础分 = 100

扣分项:
- 速度扣分: >50km/h(-3), >60km/h(-6), >80km/h(-10)
- 温度扣分: >55°C(-4), >70°C(-8)
- 电流扣分: 峰值>P99(-5), >80A(-3/次), >100A(-8/次)
- SOC扣分: <20%时长占比×50
- 能耗扣分: 百公里电耗异常(-5)
- 怠速扣分: 怠速放电比过高(-5)
```

### 3️⃣ L2 - 用户快照层 (`snapshot_layer.py`)

**功能：** 将同一用户多个合约的日指标聚合成用户级快照

**聚合规则：**

| 指标类型 | 聚合方式 | 示例 |
|---------|----------|------|
| **距离类** | SUM | 总行驶距离 = Σ各合约距离 |
| **时长类** | SUM | 总骑行时长 = Σ各合约时长 |
| **次数类** | SUM | 总换电次数 = Σ各合约次数 |
| **速率类** | 加权平均 | 平均速度 = Σ(速度×时长)/Σ时长 |
| **极值类** | MAX | 最高速度 = MAX(各合约最高速度) |
| **比例类** | 加权平均 | 高峰骑行占比 = Σ(占比×时长)/Σ时长 |
| **分类类** | 优先级取值 | 客户形态 = 改装 > 地摊 > 专送 > ... |

**空间字段传递：**
```python
df_agg['最大单合约活动半径_km'] = g['R95核心活动半径'].max()  # 已有
df_agg['R90活动半径_km'] = g['R90日常活动半径'].max()            # 新增
df_agg['最大凸包覆盖面积_km2'] = g['凸包覆盖面积'].max()         # 新增
df_agg['最大单次出行距离_km'] = g['最大出行距离'].max()          # 新增
```

**综合判定函数：**
- `_get_user_type()` : 多合约客户形态综合
- `_get_user_level()` : 多合约用户等级综合
- `_dominant_swap_period()` : 偏好换电时段综合
- `_dominant_period()` : 主要骑行时段综合

### 4️⃣ L3 - 生命周期层 (`lifecycle_layer.py`)

**功能：** 基于7天滚动窗口计算用户生命周期指标和完全体画像

#### 7天滚动计算方法

**加权平均指标（18个）：**
```python
# 使用骑行时长作为权重，避免低活跃日拉低均值
近7d平均骑行电流_A = Σ(当日电流 × 当日骑行时长) / Σ(当日骑行时长)
```

**覆盖字段：**
- 骑行指标：日均里程、时长、次数、速度、电流
- 电池指标：SOC、电耗、换电次数
- 时段指标：高峰/平峰/夜间里程与次数
- **新增**：P50/P90速度、夜间均速、取电/还电SOC、换电时段占比

**极值指标（9个）：**
```python
近7d最高速度_kmh = MAX(当日最高速度)
近7d_R90活动半径_km = MAX(R90活动半径)
近7d凸包覆盖面积_km2 = MAX(凸包面积)
# ...
```

**累积/平均指标（22个）：**
```python
近7d总行驶距离_km = Σ(当日总行驶距离)
近7d日均行驶距离_km = 近7d总行驶距离 / 有效天数
# ...
```

#### 衍生指标计算（`_add_derived_portrait_metrics()`）

| 指标名 | 计算公式 | 业务含义 |
|--------|----------|----------|
| **近7d活动集中度** | R90 / R95 | 越大越集中（固定区域活动） |
| **近7d换电友好分** | (平峰×0.6 + 深夜×0.4) × 20 | 电网友好程度（满分20） |
| **换电时段偏好_7d** | 基于占比阈值 | 偏好平峰/深夜/混合/高峰 |
| **近7d骑行规律性评分** | 出勤率 × 10 | 时间规律性（满分10） |
| **夜间高速风险** | 夜间均速分级 | ≥45高 / ≥35中 / <35低 |

#### 完全体画像文本生成（`_generate_full_portrait()`）

**输出示例：**
```
【类型】专送骑手 | 良好用户 | 生命周期:活跃

【骑行时间】惯用时段:晚间高峰 | 首次上路:07:xx / 最晚收车:22:xx | 
         出勤率:86% | 日均骑行:4.2h

【换电习惯】偏好平峰换电 | 7天共换电18次 | 
         平峰占比:61% / 深夜占比:22% | 换电友好分:15.2/20

【活动区域】广东省 深圳市 南山区 | 
         日常半径(R90):3.2km / 极限半径(R95):5.8km | 
         覆盖面积:12.5km² | 最远单次出行:8.3km | 集中度:较集中

【骑行距离】7天:186km / 日均:26.6km | 百公里电耗:2.8kWh | 月预估用电:84度

【速度画像】P50:18km/h / P90:32km/h / 峰值:48km/h | 夜间均速:28km/h（风险:中）

【电流画像】均值:12.5A / 峰值:65A | 超80A:2次

【电池状况】最低SOC:15% / 均值SOC:42% | 低电量时长占比:8% | 
         取电SOC:92% → 还电SOC:28%（消耗64%）

【风险&策略】持续高耗流 | 专送骑手关怀 | 综合评分:72.5/100
```

**涵盖9大维度：**
1. 类型（客户形态 + 等级 + 生命周期状态）
2. 骑行时间（惯用时段 + 出勤率 + 日均时长）
3. 换电习惯（偏好时段 + 次数分布 + 友好评分）
4. 活动区域（地理位置 + 半径 + 面积 + 集中度）
5. 骑行距离（总量 + 日均 + 电耗 + 月预估）
6. 速度画像（P50/P90 + 峰值 + 夜间风险）
7. 电流画像（均值 + 峰值 + 超阈值次数）
8. 电池状况（SOC水平 + 低电量时长 + 换电消耗）
9. 风险&策略（风险标签 + 策略建议 + 综合评分）

### 5️⃣ L3+ - 评分分类层 (`score_layer.py`)

**功能：** 基于动态阈值进行用户评分、分级、风险标记

#### 动态阈值系统

**原理：** 使用历史数据的统计分位数作为自适应阈值

```python
# 从 thresholds_baseline.json 加载基准数据
baseline = {
    'avg_cur_P50': 15.2,    # 历史平均电流中位数
    'avg_cur_P95': 28.7,    # 历史平均电流95分位
    'max_cur_P99': 65.3,    # 历史最大电流99分位
    # ...
}

# 当前用户的相对位置
user_percentile = (user_avg_cur - baseline_P50) / (baseline_P95 - baseline_P50)
```

#### 评分维度（100分制）

| 维度 | 权重 | 扣分条件 |
|------|------|----------|
| **平均电流** | 25分 | >P95开始扣，>P99扣完 |
| **最大电流** | 20分 | >保护板电流(60A)开始扣 |
| **超80A次数** | 15分 | 每次-3分 |
| **月用电量** | 15分 | >150度开始扣，>250重度扣 |
| **SOC低电量** | 10分 | <20%时长占比×50 |
| **温度** | 8分 | >55°C(-4), >70°C(-8) |
| **速度** | 7分 | >50(-3), >60(-6), >80(-10) |
| **换电频率** | - | >3次/天开始扣 |
| **SOC奖励** | +3分 | SOC在30%-80%且无低电量 |

#### 风险标签体系（优先级从高到低）

| 标签 | 触发条件 | 说明 |
|------|----------|------|
| **暴力放电** | 超100A≥2次 或 累计≥0.5h | 最高优先级 |
| **极端电流** | 最大电流>P99 | 严重警告 |
| **超保护板电流** | 最大电流>60A | 保护板风险 |
| **频繁超80A** | 有超80A记录 | 中等风险 |
| **中高电流频繁** | 超60A>10次 | 轻微提醒 |
| **持续高耗流** | 平均电流>P95 | 长期高负荷 |
| **深度亏电** | SOC<10%或最低<10% | 电池损伤风险 |
| **低电量告警** | SOC<20%时长>0 | 一般提醒 |
| **电池高温** | 温度>55°C或>70°C | 热失控风险 |

#### 用户等级划分

| 等级 | 分数区间 | 典型特征 |
|------|----------|----------|
| **优质用户** | ≥85 | 低电流、高效率、规律使用 |
| **良好用户** | 70-84 | 轻微偏差，整体健康 |
| **普通用户** | 55-69 | 正常使用，有改进空间 |
| **高损耗用户** | 40-54 | 高能耗或频繁深放 |
| **暴力用户** | <40 或 满足暴力条件 | 严重异常，需关注 |
| **观察期** | 新用户(<3天) | 数据不足，暂不评级 |
| **沉默用户** | 7天无出勤 | 可能流失 |

#### 差异化策略建议

**基础策略表：**
```python
{
    '优质用户': '留存激励',
    '良好用户': '维持服务',
    '普通用户': '引导升级',
    '高损耗用户': '限制预警',
    '暴力': '清退处理',
    '观察期': '新手引导',
    '沉默用户': '激活唤醒'
}
```

**差异化增强：**
- 专送骑手 + 普通/良好 → **专送骑手关怀**
- 地摊/储能 → **非正常用电核查**
- 改装/超速车 → **风险用户核查**
- 众包骑手 + 普通 → **众包骑手引导**
- 高损耗 + 习惯晚上 → **夜间高损耗预警**

## 🔧 性能优化特性

### L0 层优化

| 优化项 | 效果 | 说明 |
|--------|------|------|
| **并行处理** | ~8×提速 | ProcessPoolExecutor，8进程并行 |
| **批处理** | 内存稳定 | 每100文件一批，避免OOM |
| **智能文件过滤** | 90%+ I/O节省 | 预读50行提取日期，跳过已有数据 |
| **按日期拆分写入** | 无需GroupBy | 批次内直接按日期写临时文件 |
| **增量检测** | 幂等执行 | 自动检测已有日期，避免重复处理 |

**典型性能（8706个文件）：**
```
首次全量: ~150s（88批次）
增量更新: ~30-40s（5-10批次，过滤后）
重复运行: ~30s（全部跳过）
```

### L1-L3 层优化

- **向量化计算**：使用 NumPy/Pandas 向量化操作，避免循环
- **惰性求值**：只在需要时计算复杂指标
- **内存优化**：及时释放中间变量
- **类型优化**：使用合适的数据类型（category, int32等）

## 🐛 常见问题排查

### Q1: L0 处理很慢？

**检查项：**
1. 是否首次运行？（首次需处理全量数据）
2. 是否有大量新日期数据？
3. `existing_dates` 是否正确检测？

**优化方案：**
```python
# 在 config.py 中调整
MAX_WORKERS = 8  # 增加并行度
BATCH_SIZE = 200  # 增大批次大小（但会增加内存占用）
```

### Q2: KeyError: '统计日期时间'？

**原因：** L0 不输出此字段，应使用 `时间戳` 字段

**修复：** 已在 fact_layer.py 中修复（v2.0+）

### Q3: 导入错误 ModuleNotFoundError？

**原因：** Python 路径问题

**解决方案：**
```bash
# 推荐方式1：直接运行
python src/run_pipeline.py --mode full

# 推荐方式2：模块方式
cd src
python -m run_pipeline --mode full

# 如果仍有问题，检查 sys.path
import sys
sys.path.insert(0, '项目根目录')
```

### Q4: 字段缺失或数值为空？

**可能原因：**
1. 原始数据缺少对应字段（如 `电池SOC`, `电池id`）
2. 该用户当天无相关行为（如无换电记录）

**设计原则：** 所有字段均有默认值，不会导致程序崩溃

### Q5: 如何只重新计算某一天的数据？

```bash
# 删除该天的输出文件，然后重新运行
del data/raw/2026-04-21.parquet
del data/fact/daily/2026-04-21.parquet

# 增量运行会自动补齐
python src/run_pipeline.py --mode incremental
```
